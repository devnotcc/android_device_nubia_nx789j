# Display AIDL -ndk libraries, shipped as blobs under RENAMED modules.
#
# Found by auditing every unresolved DT_NEEDED in the built vendor image after
# build 11 (2026-09-13). config-V7 is the one that blocked boot - it is needed
# by /vendor/lib64/libops.so:
#   E ListenerMngr: Init dlopen(libops.so, RLTD_NOW) is failed....
#     dlopen failed: library "vendor.qti.hardware.display.config-V7-ndk.so"
#     not found: needed by /vendor/lib64/libops.so
#   E QSEECOMD: ERROR: Failed to start listner services.
# qseecomd opens /dev/smcinvoke fine, then exits 255 when its listener manager
# cannot load, so the QTI KeyMint HAL never registers IKeyMintDevice, keystore2
# crashes on a 6-attempt retry loop, vold blocks on android.security.maintenance
# and /data never mounts.
#
# WHY ";MODULE_SUFFIX=_nx789j" AND NOT A PLAIN BLOB LINE:
# vendor/qcom/opensource/commonsys-intf/display/aidl/{aiqe,color,composer3,
# config,demura,postproc} define these as aidl_interface modules with
# vendor_available: true. A prebuilt with the SAME module name is treated as a
# prebuilt-replaces-source candidate, and soong then rejects it because the
# partitions differ:
#   error: module "vendor.qti.hardware.display.aiqe-V2-ndk" ...
#     partition is different: system(vendor.qti.hardware.display.aiqe-V2-ndk)
#     != vendor(prebuilt_vendor.qti.hardware.display.aiqe-V2-ndk)
# MODULE_SUFFIX (extract_utils/makefiles.py:154) sets stem to the real filename
# and appends the suffix to the module name only, so the file still installs as
# vendor/lib64/vendor.qti.hardware.display.*-ndk.so with no name clash.
#
# WHY NOT BUILD THEM FROM SOURCE VIA PRODUCT_PACKAGES:
# tried, does not work. Neither the bare name nor the .vendor variant is a make
# module ("includes non-existent modules in PRODUCT_PACKAGES") and .vendor is
# not a ninja target either. Soong does reference
# vendor.qti.hardware.display.config-V7-ndk.vendor in LOCAL_SHARED_LIBRARIES for
# libops.so, but it never exports it as installable - and a prebuilt's
# shared_libs only feeds check_elf_file, it does not create an install rule.
# That is exactly why these were missing: the ONLY consumers are blobs.

# Adreno GLES driver - dlopen'd by libEGL, so no DT_NEEDED audit can find it.
#
# Build 14 (2026-09-13) was the first to mount /data. It then stalled on the OEM
# splash with surfaceflinger and zygote restarting:
#   E libEGL : eglInitializeImpl:283 error 3008 (EGL_BAD_DISPLAY)
#   F SurfaceFlinger: failed to initialize EGL
#   F DEBUG : ... SkiaGLRenderEngine::create ... Abort message: 'failed to initialize EGL'
# The kernel side was fine ("DRIVER KGSL Ready"). libEGL loads
# /vendor/lib64/egl/lib{EGL,GLESv1_CM,GLESv2}_<ro.hardware.egl>.so as a set;
# libGLESv2_adreno.so was never listed, so the Adreno driver failed to load and
# libEGL reported no display. libEGL_adreno.so was only listed because the
# undefined-module loop found something DT_NEEDED-ing it - GLESv2 and
# q3dtools_adreno are loaded purely by name and slipped past every link-time
# check. All their DT_NEEDED deps were already shipped (verified).
# Neither name is a source module anywhere in the tree, so plain lines are safe.
vendor/lib64/egl/libGLESv2_adreno.so
vendor/lib64/egl/libq3dtools_adreno.so

# Display composer + allocator: init rc, allocator binary, VINTF fragments.
#
# Build 15 (2026-09-13): EGL came up, then SurfaceFlinger aborted 67 times with
#   F SurfaceFlinger: failed to get hwcomposer service
#   I HidlServiceManagement: Trying to get transport of
#     android.hardware.graphics.composer@2.1::IComposer/default
# SurfaceFlinger only falls back to looking for the HIDL composer when
# android.hardware.graphics.composer3.IComposer/default is not DECLARED in the
# vendor VINTF manifest. Neither a composer nor an allocator process existed.
# What was missing, compared with the stock dump:
#   - vendor.qti.hardware.display.composer-service.rc  -> the composer binary was
#     shipped (see the note above about QMAA), but with no rc init never started it
#   - vendor.qti.hardware.display.allocator-service    -> binary AND rc absent
#   - the two VINTF fragments declaring composer3 v3 and allocator v2
#
# The allocator binary shadows a source module of the same name
# (hardware/qcom-caf/sm8750/display/hal/gralloc), exactly as composer-service
# already does - both are vendor-partition, so extract-utils' prefer:true works
# there. (The display -ndk collision earlier was a SYSTEM vs vendor mismatch.)
#
# The composer3 fragment also declares vendor.qti.hardware.display.{aiqe,color,
# config,postproc}; those are added as optional to framework_compatibility_matrix.xml.
vendor/bin/hw/vendor.qti.hardware.display.allocator-service
vendor/etc/init/vendor.qti.hardware.display.allocator-service.rc
vendor/etc/init/vendor.qti.hardware.display.composer-service.rc
vendor/etc/vintf/manifest/vendor.qti.hardware.display.allocator-service.xml
vendor/etc/vintf/manifest/vendor.qti.hardware.display.composer-service3_v3.xml
